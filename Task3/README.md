# Оценка Data Encryption at Rest and In Transit

## 1. Классификация данных

Данные классифицируются по чувствительности и регуляторному статусу:

| Уровень | Примеры данных | Регуляторный статус |
| --- | --- | --- |
| Restricted | Диагнозы, анализы, анамнез, паспорт, СНИЛС, платёжные данные, ключи шифрования | Специальные категории ПДн + врачебная тайна (152-ФЗ, 323-ФЗ) |
| Confidential | Телефон, email, адрес, факт обращения, история платежей, audit logs | Персональные данные, коммерческая информация |
| Internal | Данные ТМЦ, обезличенные данные для BI | Операционные / обезличенные |

## 2. Обоснование необходимости защиты

- Restricted: специальные категории персональных данных и врачебная тайна требуют повышенных мер защиты. Утечка ведёт к штрафам, репутационному ущербу и потере доверия клиентов.

- Confidential: обычные ПДн и финансовые данные. Нарушение 152-ФЗ и риск мошенничества / социальной инженерии.

- При планируемом пятикратном росте объёма данных риски возрастают пропорционально, поэтому защита должна быть заложена на уровне архитектуры (Privacy by Design).

## 3. Таблица защиты данных

| Данные | В чём необходимость защиты | Инструменты защиты |
| --- | --- | --- |
| Идентификационные ПДн (ФИО, паспорт, СНИЛС) | 152-ФЗ, риск кражи личности | AES-256 field-level, tokenisation, TLS 1.3, Vault |
| Контактные данные (телефон, email) | Социальная инженерия | Encryption at rest, masking в UI, TLS |
| Данные о здоровье (диагнозы, анализы, анамнез) | Специальная категория ПДн + врачебная тайна | Field-level encryption, ABAC, audit, mTLS |
| Платёжные данные | Мошенничество, финансовые риски | Tokenisation, isolated domain, TLS |
| Факт обращения / запись к врачу | Врачебная тайна | Encryption, минимизация логов, ABAC |
| Ключи шифрования | Компрометация = утечка всех данных | Vault / HSM, rotation, separation of duties |
| Audit logs | Целостность расследований | Immutable encrypted storage |
| Обезличенные данные для BI/ML | Utility + защита privacy | Anonymization pipeline (k-anonymity) |

## 4. Основные инструменты защиты данных

At Rest: AES-256-GCM, field-level encryption, HashiCorp Vault / Yandex KMS, tokenisation  

In Transit: TLS 1.3, mTLS (для лаборатории и критических интеграций)  

Контроль доступа и аудит: RBAC + ABAC (OPA/Cerbos), immutable audit log, Data Lineage  

Автоматизация: CI/CD-проверки на наличие тегов и encryption, SIEM/UEBA, DLP
